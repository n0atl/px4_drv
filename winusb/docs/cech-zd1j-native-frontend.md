# CECH-ZD1J復調器のホスト内統合

対象はWinUSB版のSony torne CECH-ZD1J。比較元は`tools/torne_frontend/upstream.json`で固定した
coaxのDiB8000/DiB0090実装と、ローカルの探索終了通知追加分。
後続のログ・バッファ設定と、任意の未訂正TS出力については
[ログと低ビットレート受信](torne-weak-signal.md)を参照。

## 構成と維持する動作

Go helperの復調器処理をC++へ移植し、`DriverHost_PX4.exe`へ静的に組み込む構成。
校正値、チューナーの状態、探索状態は物理デバイスのセッションごとに保持する。
USB、TS、カードの所有権と既存の排他順序は`ExperimentalSession`に残る。
PX-W3U4、PX-MLT5PEなどの機種別処理と共通IPCの変更は不要。

移植対象にはレジスター表、GPIO、PLL、校正、AGC、探索、状態取得、スリープを含む。
周波数範囲、待機時間、探索の期限と無信号確定条件は比較元と同じ。
I2Cの8bitアドレスとrepeated-startを維持し、各レジスター操作では期限を更新せず、
操作全体の期限と抜去イベントをネイティブのI2C・待機アダプターで確認する。
Windowsの短い待機はGo runtimeと同じ高精度waitable timerを使い、通常のtimeout待機で
OSのtick単位の遅れが積み重なることを避ける。高精度flag非対応時は通常timerを使う。

`dib8096_native_generated.inc`はGoの型情報付きASTから生成するC++ソース。
固定幅整数の剰余とシフト、sliceの参照共有、名前付き戻り値を明示的に変換する。
`port_native.go.txt`は開発用の変換器で、通常のC++ビルドと実行にGoは不要。
バス、GPIOコールバック、エラー境界は手書きのC++アダプターで接続する。
元の著作権とGPLv2の表示、対応するソースと生成手順を配布時に保持する。

## 検証

`python tests/check_torne_native.py --arch x64 --regenerate`と`--arch x86`で、
既存GoテストのfakeChip/fakeClockを使った通信列とC++版を比較できる。
比較対象は全I2C要求と応答、待機時間、操作結果。正常局、無信号、探索タイムアウト、
未知のチップ、I2C失敗、待機失敗、CBANDおよびスリープ後の再選局を含む。
模擬試験にはUSBアクセスが含まれないため、受信成功の判断には別途実機確認が必要。

実機比較は利用中のアプリと競合しない隔離フォルダーで行い、32bit/64bit、2台受信、
無信号後の復帰、カード通信との同時利用を確認する。PX実機との同時利用と長時間録画は
別の検証項目。検証前の版とログを保持し、稼働中の配布フォルダーへの上書きは避ける。

## 実機確認（2026-10-27）

検証環境はWindows、CECH-ZD1Jを2台、B-CASは片側の1枚。
アンテナは同じ系統から接続し、試験途中の接続変更後は受信局を41・42・47・49ch、
無信号局を17・21・26chとしてGo版とC++版を同条件で比較した。
変更前のチャンネル番号で行った試験は両版とも不安定で、合格の根拠から除外した。

最終C++版はx86/x64の両ホストで、2台を同時に使って各正常局を2秒ずつ受信し、
途中に3つの無信号局を挟んだ。正常局はすべて受信し、TS同期・TEI・CC・形式・読出し異常は0。
無信号確定は613～670msで、その後の正常局へ復帰した。初回選局は約2.4～2.6秒、
以降の正常局は約1.3～1.8秒で、Go比較版と同程度。
各ホストで32bit WinSCardのAPDUは5秒間、19回成功・失敗0、最大63～64ms。
64bit WinSCardからの列挙、カード接続、空スロットのエラーも確認した。

追加のx86試験ではカード通信を35秒間継続しながら、2台で41→17→47chと49→17→42chを
選局し、正常局を各10秒間受信した。各受信区間で113,664パケット、TS同期・TEI・CC・
形式・読出し異常は0。APDUは111回成功・失敗0。ただし初期化・選局と重なるカード通信に
最大3,753msの遅延があり、応答が一定時間内に収まる保証は未確認。

既存PX系の機種別受信・カード実装と、従来のホスト設定部分は保持している。
PX実機との同時受信、長時間録画、TVTestでの映像・スクランブル解除、EDCBの予約録画は
このC++版では未確認。模擬試験と短時間受信だけで本番運用の安定性を断定できない。
